# Agent Authority MCP gate

Phase 4 mounts an optional MCP v2 endpoint at `/mcp` on Legacy Control Lab's existing HTTP server. It is disabled by default. Enable the synthetic local gate with:

```text
LCL_AGENT_AUTHORITY_ENABLED=true
LCL_AGENT_TARGET=lcl
```

No additional port, API key, model provider, or live IBM i connection is used. Any target other than `lcl` fails closed during startup.

The endpoint exposes only the six reviewed Agent Authority tools. It can observe, request an approval-bound mutation, and poll proposal status. It cannot approve, deny, execute an approved proposal, invoke the counterfactual harness, or execute arbitrary commands.

## Authority Desk

When enabled, the same server-owned Agent Authority runtime also serves the human Authority Desk at `/lab/authority/`. Every `/api/agent-authority/*` request requires the token for an exact, fresh, signed-on live LCL operator session. The Desk never accepts a caller-supplied approver identity and approval must echo the displayed action hash.

There is no execution endpoint. Approve calls the existing protected `OperatorApprovalService`, while MCP remains observe, request, and poll. Disabling Agent Authority removes `/mcp`, the Desk API, and the Desk static files together.

## Identity limitation

Phase 4 represents all MCP requests as one server-created opaque local synthetic Agent Authority principal. A fresh request ID is generated by the server for each tool invocation. MCP `clientInfo` is retained only as self-reported display metadata and never affects authorization or principal identity.

This is not authenticated multi-client isolation. A verified transport identity must be bound to distinct principals before any future real IBM i target can be considered safe.
